Conexão com o equipamento

Uma página comum não consegue conversar com qualquer máquina via USB ou Bluetooth de forma genérica: isso exige APIs específicas do navegador (WebUSB, WebSerial, WebBluetooth), protocolo do fabricante do equipamento, e normalmente um serviço rodando na borda (gateway OPC UA/Modbus) fazendo a ponte. Aqui essa etapa é simulada, do mesmo jeito que o painel MES simula o SAP — o objetivo é mostrar a lógica de diagnóstico e decisão, que é a parte que realmente importa para o problema descrito na vaga.

O motor de diagnóstico

Não é um modelo de linguagem rodando aqui dentro — é um mecanismo de regras e correspondência por palavras-chave: ele compara o código de falha e o sintoma digitado com a base de problemas conhecidos e com o texto dos manuais cadastrados, e calcula uma confiança pela quantidade de termos em comum. É simples de propósito: dá para entender exatamente por que o sistema decidiu o que decidiu, o que é importante quando a decisão pode acionar uma correção automática.

Por que só falhas técnicas se resolvem sozinhas

O botão "Resolver agora" só existe para causas classificadas como técnicas/sistêmicas — coisas como reiniciar uma sessão de comunicação, limpar uma fila de erro ou reenviar uma mensagem ao SAP. Falhas físicas (motor, rolamento, sensor danificado) sempre geram uma ordem de serviço para um técnico, nunca uma ação automática — não faz sentido, e não é seguro, um software "consertar" uma peça sozinho.
